# sdks/go/ — Go Client SDK

A thin Go client for [contracts/openapi/bongopay.yaml](../../contracts/openapi/bongopay.yaml).
Its own Go module (`go.mod`), independent of
[implementations/reference/](../../implementations/reference/README.md) — see
[ARCHITECTURE.md §7](../../ARCHITECTURE.md#7-sdk-boundary): SDKs are idiomatic per-language
clients over the canonical contract, not tied to any one implementation's internals (and indeed
cannot import them — `internal/` packages aren't importable across module boundaries).

## What's Generated, What's Hand-Written

- **`generated/client.gen.go`** — the request/response types (`Payment`, `PaymentRequest`,
  `Money`, etc.), generated by [`oapi-codegen`](https://github.com/oapi-codegen/oapi-codegen)
  from `contracts/openapi/bongopay.yaml`. Carries this repo's standard generated-file header
  (see [AGENTS.md §11](../../AGENTS.md#11-identifying-generated-files)) — edit the OpenAPI
  contract and run `make generate`, never this file directly.
- **`client.go`** — a thin, hand-written HTTP client (`New`, `InitiatePayment`, `GetPayment`)
  built on those generated types.

The client itself is hand-written rather than also generated because `oapi-codegen`'s client
generator pulls in `github.com/oapi-codegen/runtime` purely to encode path parameters using
OpenAPI's style/explode rules — machinery this API doesn't need, since its only path parameter
(`GET /payments/{id}`'s `id`) is a plain string. Per
[docs/development/dependency-policy.md](../../docs/development/dependency-policy.md)'s "can the
standard library solve this instead?" question: yes, trivially (`url.PathEscape`), so pulling in
a dependency for it wasn't worth it. If this API's parameter surface ever gets genuinely
complex, revisit this call — the tradeoff, not the conclusion, is what should carry forward.

## Regenerating

```bash
make generate    # from the repo root; see scripts/generate.sh
```

Requires Go (for `go run`'ing `oapi-codegen`) — no separate install step, and no dependency added
to this module's own `go.mod`, since the generator itself isn't imported, only invoked.

## Usage

```go
client := bongopay.New("http://localhost:8080")

result, err := client.InitiatePayment(ctx, bongopay.PaymentRequest{
    Provider:          generated.Provider{Id: "SIMULATOR"},
    Amount:            generated.Money{Value: 5000, Currency: generated.Currency{Code: "TZS"}},
    CustomerReference: generated.CustomerReference{},
    IdempotencyKey:    "demo-1",
})

payment, err := client.GetPayment(ctx, result.Payment.Id)
```

A non-2xx response returns `*bongopay.APIError` (`StatusCode` + `Message`) — see
[contracts/openapi/README.md](../../contracts/openapi/README.md) on why the `Error` schema
itself is provisional, not the canonical error taxonomy.

## Testing

`client_test.go` builds `implementations/reference/cmd/server` into a temp binary, runs it, and
exercises the client against that real, running server over real HTTP — not a mock — the same
discipline used to verify the Docker image and CLI. Skips (not fails) if
`implementations/reference/` isn't found at the expected relative path.

```bash
go test ./...
```
